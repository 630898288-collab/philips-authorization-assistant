## 写入及截图

1. `lark-cli base +field-list --base-token ... --table-id ... --as user`；需要姓名人员字段时解析用户本人 ID，不把创建人或 bot 误当申请人；先用检索避免重复。附件类字段通过上传接口处理。
2. `lark-cli base +record-batch-create --base-token ... --table-id ... --json '{"create_records":[{...}]}' --as user`；字段值依实时 schema 与类型编码。获得 record_id 后使用 `+record-get`（必要时短暂重试以等待一致性）核对；附件通过 `+record-upload-attachment` 并再核对。`+record-share-link-create` 获取具体记录 URL。
3. 用可用的用户已登录浏览器／电脑操作工具打开上一步**真实飞书记录**或其分享页，定位完整的申请字段，确保所截记录的 record_id/主体与回读一致；若一屏不足就分多张截图。捕获原始界面并将真实截图作为当前对话图片或可访问的本地图片交付用户，说明可用于国内 OA 附件。不要捕获无关记录或将合成的 HTML、模拟界面、文字概览称为飞书截图。截图含业务资料，按实际使用场景裁切。
4. 没有可用已登录浏览器、界面无法展示或当前环境不能导出截图时：如实说明未取得截图；仍交付核对结果、该记录链接，并指出用户打开记录后自行截图。必要时请用户协助或接管浏览器。不要反复创建记录，也不要停止其他已授权任务。
5. 海外用户仍可获得截图和链接，明确其不需要 OA。不要主动通过飞书聊天发送给第三人；“发给我”优先在当前对话展示。


## 国内 OA 接续指引

完成下列任一国内多维表登记后，主动在最终回复的“下一步”提醒用户：**请由本人继续提交 OA，当前仅完成多维表登记，未完成 OA 审批或取得授权。** 根据本次类型直接给出入口和所需截图；当用户不懂时，展开以下步骤，并以当前 OA 界面与现行受控规范为准。

- **主授权信**：OA → 流程 → 新建流程 →「飞利浦相关核心文件申请」。将登记记录截图放入「请示内容」，写清客户/平台、具体用途和水印内容；按界面要求保存并提交。审批后在流程中下载已加水印的主授权信，核对水印用途再外发。
- **销售一级授权**：OA → 流程 → 新建流程 →「飞利浦水健康品牌授权申请」→「销售部门一级授权」。附登记截图；首次申请按要求附已签销售合同电子档及其 OA 流程电子附件，续期附上一年度授权信扫描件；特殊一级材料不全还须 CEO 同意证据。先保存，再提交；跟进审批及授权文件回传。其他业务板块的 OA 流程名称以实际系统为准。
- **国内销售二级标准版**：OA → 流程 → 新建流程 →「飞利浦水健康品牌授权申请」→「销售部门二级授权」。填写系统要求字段、附登记截图和首次/续期对应材料；电子章选「公章」，合同模板选「飞利浦品牌经销商平台授权书-二级授权」，先保存再提交。非标准版需走相应非标准 OA 申请、附合作方文件，审批后按规范线下盖章；OA 具体名称以系统为准。
- **供应商二级**：OA → 流程 → 新建流程 →「飞利浦水健康品牌授权申请」→「供应链」。按界面填写主体、区域、产品、商标号及期限，附登记截图与所需合同材料；电子章选「公章」，模板选「飞利浦品牌供应商授权书-供应链」，先保存再提交。

示例提醒：“多维表登记已完成：[记录链接]。**下一步请你在 OA 自行提交「飞利浦水健康品牌授权申请」并选择「销售部门一级授权」**，附本次登记截图及相应合同材料，先保存再提交。我可以按页面一步步告诉你怎么操作。”只在匹配该业务时使用对应步骤，不能机械套用示例。

截图未能真实获取时，明确“截图尚未取得”，提供记录链接请用户打开后截图；不可将自动生成的摘要冒充系统截图。海外同事不需 OA；仅做商标查询、独立站登记、特殊渠道或白名单时，按实际需要说明邮件/审核动作，不凭国内地点推定一定需要 OA。
