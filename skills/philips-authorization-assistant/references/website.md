目标为独立站的**实际管理表**，不是名称相近的 LOA Base 镜像：`base_token=Vkiibw559axcP0sHDIhc5OdNnUh`，`table_id=tblBruR3ONA7sgid`，[直达表](https://deerma66.feishu.cn/wiki/Kz61wxL56iDGvPkZDjBcLlBrngh?table=tblBruR3ONA7sgid)。2026-11-19 校验有 31 字段，包括站点编号、代理商、网站负责人、所属区域、目标市场、站点类型、主域名、建站平台、产品范围、网站目的、预计日期、授权文件、Gloria/Alex/MU Head 审核、Ferry 品牌检查、法务/政策页、SEO、上线结论、下一动作及备注。实际字段、选项和可写权限每次实时读取。

## 登记与邮件

用户明确希望申请时，收集代理商主体、项目/网站负责人、地区 MU（MoW/NA/EU 等）、目标国家、网站类型、主域名或拟定域名、建站平台、产品范围、站点目的、预计时间、授权文件（如适用）及补充说明；区分“不适用”“尚未确定”与空值。市场与 MU 对应不明确时问用户，不按国家想当然推断。查是否已有同域名、同代理商同一项目避免重复，必要时询问新建还是更新。只写当前 schema 允许的申请信息，附件按专用接口；不要填写审核结果、上线许可或他人的责任人字段。

核验后提供站点编号、记录链接和真实截图（见 authorization.md）。若附件上传失败如实说明并在原记录续办。登记后**还有邮件审核步骤**：邮件主送 Alex，抄送 Gloria 及对应 MU 总；MoW 为 Daniel Abbo，北美为 David Farmer，欧洲为 Jakub Grosman。多区域涉及多名负责人时全部列出；CN/AU 等当前未给出对应负责人，不猜测，先问用户。先按 [邮件办理](email.md) 搜索并核实邮箱，基于当前请求给出草稿或直接发送选项；用户选择草稿时创建邮箱草稿。不能将登记、邮件发送或某一单项通过等同网站批准上线；未经明确发送授权不能发。

邮件应有真实代理商、地区、国家、网站目的、域名、品类、站点状态、需要的审批动作、申请人和该记录链接，任何未知项标“待补充”或先问；不要称“已批准”。附截图或用户提供资料时先确认附件是实际文件，勿将无权分享的资料转发给无权限人。

## 查询申请进度

通过 DTC 编号、域名、代理商名或记录链接定位；多条匹配则让用户确认。实时读取当前记录：Gloria 审核结果、Alex 审核意见、MU Head 审核意见、Ferry 内容品牌检查、SEO、法务/政策页、上线结论、当前状态、下一动作、备注、最近跟进日期；仅报告有值字段，空白标“未记录”，不要自行推断已批准/驳回或邮件已发送。`Current Owner / 当前责任人` 是 updated_by（最后修改人），不能当业务责任人；网站负责人是独立字段。给记录直达链接和具体下一步；如果需要邮件状态，邮件箱中搜索对应邮件并区分草稿、已发送和已投递，不把 Base 字段当邮件发送证据。
